# Чем она отличается от других библиотек?

> Это перевод [страницы на английском языке](../../guide/comparison.md). Перевод ещё не проверен носителем языка; если тексты расходятся, верной считается английская страница.

**Коротко.** Большинство библиотек хорошо покрывают одно семейство методов.
sequential-analysis объединяет основные семейства последовательного
статистического вывода (sequential inference) за одним интерфейсом:

* SPRT и оптимальные планы;
* групповые последовательные дизайны;
* критерии и доверительные последовательности, валидные в любой момент
  (anytime-valid);
* обнаружение разладки;
* фильтры в пространстве состояний (state-space filters).

Что она добавляет помимо самих методов:

* каждая процедура заявляет свою гарантию (`exact`, `asymptotic`, `model`,
  ...);
* состояние любого запуска можно сохранить в контрольную точку и продолжить
  бит в бит;
* форматы специфицированы и исполняются второй реализацией на TypeScript;
* обязательных зависимостей нет.

Если вам нужен только один из перечисленных ниже методов и вы уже
пользуетесь библиотекой, которая на нём специализируется, продолжайте ею
пользоваться. Таблица показывает, где какой инструмент является
естественным выбором. Описания отражают основное назначение каждой
библиотеки по состоянию на октябрь 2026 года и не являются полным перечнем
её возможностей.

| Задача | Естественный выбор | Что предлагает sequential-analysis |
|---|---|---|
| критерии с фиксированным объёмом выборки, регрессия, мощность | scipy.stats, statsmodels | не её назначение |
| групповые последовательные дизайны для регистрационного досье | rpact, gsDesign (R) | те же дизайны, сверенные с rpact в её наборе тестов; проводит исследование шаг за шагом с контрольными точками |
| доверительные последовательности, e-значения | confseq (Python), safestats (R) | доверительные последовательности для средних, квантилей, коэффициентов регрессии, эффектов в двух выборках; e-BH и e-LOND для множества критериев |
| A/B-тесты как платформа с интерфейсом | GrowthBook, Statsig, Eppo, Optimizely (платформы) | движок для встраивания: точные критерии для конверсии, ограниченных метрик и интенсивностей, SRM, FDR по метрикам |
| офлайн-сегментация завершённого ряда по точкам разладки | ruptures (Python), changepoint (R) | онлайн-обнаружение по мере поступления данных: CUSUM, Shiryaev–Roberts, e-детекторы, байесовское онлайн-обнаружение точек разладки |
| фильтры Калмана | filterpy, statsmodels state space | фильтр Калмана, робастный фильтр Калмана, частичные и HMM-фильтры, со сглаживанием и контрольными точками |
| GARCH | arch | GARCH(1,1) и GJR, подогнанные к максимуму arch (проверено в тестах), затем работают онлайн |
| скрытые марковские модели | hmmlearn | онлайн-фильтр, Baum–Welch, согласованный с hmmlearn, онлайн-EM |
| прогнозирование | statsmodels и другие | прогнозы ETS и AR, согласованные с statsmodels, обучаемые онлайн, с конформными интервалами |

## Когда другой инструмент лучше

* **Регистрационное досье для регулятора.** rpact широко используется для
  этой цели, и его разработчики предлагают документацию по валидации.
  sequential-analysis совпадает с ним на тех дизайнах, которые она
  покрывает, но спонсору всё равно пришлось бы её валидировать.
* **Большие офлайн-анализы на массивах.** Библиотеки на основе numpy быстрее
  в расчёте на одно наблюдение. sequential-analysis рассчитана на обработку
  по одному наблюдению; стоимость каждой процедуры см. на странице
  [Скорость](../../performance.md).
* **Методы, которых в ней нет.** В ней пока нет двухвыборочного критерия
  для медиан, многомерных процессов Хоукса и моделей ARIMA с членами
  скользящего среднего. Что добавлено, см. в [журнале изменений](../../changelog.md).
