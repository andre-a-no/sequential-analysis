# Как обнаружить изменение в потоке измерений?

> Это перевод [страницы на английском языке](../../guide/change-detection.md). Перевод ещё не проверен носителем языка; если тексты расходятся, верной считается английская страница.

**Коротко.** Используйте онлайн-детектор разладки (change-point detector).
Он следит за потоком и подаёт сигнал тревоги, как только распределение,
по-видимому, изменилось. Ложные тревоги контролируются **средней длиной
серии** (average run length, ARL) — ожидаемым числом наблюдений до ложной
тревоги, пока ничего не изменилось. В sequential-analysis:

| Что известно до изменения | Процедура | Гарантия |
|---|---|---|
| оба распределения (например, нормальное, среднее 70 → 71) | `CUSUM`, `ShiryaevRoberts` | exact: ARL ≥ e^threshold |
| только среднее и границы значений | `MeanEDetector` | exact для любого такого распределения |
| только квантиль (например, 95-й процентиль задержки) | `QuantileEDetector` | exact для любого распределения |
| модель с неизвестными параметрами до и после | `BayesianChangePoint` | в рамках модели и априорного распределения |

## Датчик, у которого смещается среднее

Датчик температуры показывает 70,0 °C с шумом со стандартным отклонением
0,5. Начиная с 600-го показания среднее равно 70,4. CUSUM с порогом
log(1000) ≈ 6,9 имеет ARL не менее 1000 показаний:

```python
import math
import random

from sequential_analysis.procedures import CUSUM, Gaussian

rnd = random.Random(1)
readings = [rnd.gauss(70.0, 0.5) for _ in range(600)] + [rnd.gauss(70.4, 0.5) for _ in range(400)]

detector = CUSUM(Gaussian(sigma=0.5), theta0=70.0, theta1=70.4, threshold=math.log(1000))
state = detector.initial_state()
for t, x in enumerate(readings, start=1):
    state, out = detector.step(state, {"x": x})
    if out.alarm:
        print(f"alarm at reading {t}, {t - 600} readings after the shift")
        break
```

```text
alarm at reading 615, 15 readings after the shift
```

Сдвиг меньше одного стандартного отклонения невозможно заметить на глаз ни
в одном отдельном показании. CUSUM накапливает свидетельства и находит его.

## Когда показания не нормальны

ARL у CUSUM соблюдается, только если показания следуют тем распределениям,
которые вы ему задали. На скошенных данных (амплитуды вибрации, задержки,
длины очередей) он подаёт ложные тревоги гораздо чаще запланированного.
E-детекторам (e-detectors) нужно гораздо меньше:

* `MeanEDetector` нужны среднее до изменения и границы значений.
* `QuantileEDetector` нужен только квантиль до изменения.

Их ARL не меньше целевого для **любого** распределения с таким средним или
квантилем:

```python
from sequential_analysis.procedures import QuantileEDetector

rnd = random.Random(2)
vibration = [rnd.lognormvariate(0.0, 0.8) for _ in range(800)] + [rnd.lognormvariate(0.5, 0.8) for _ in range(400)]
q95 = math.exp(0.8 * 1.6449)          # the 95th percentile before the change
p95 = QuantileEDetector(q0=q95, p=0.95, arl=1000, direction="increase", statistic="cusum")
state = p95.initial_state()
for t, x in enumerate(vibration, start=1):
    state, out = p95.step(state, {"x": x})
    if out.alarm:
        print(f"the 95th percentile rose: alarm at reading {t}, {t - 800} readings after the change")
        break
```

```text
the 95th percentile rose: alarm at reading 887, 87 readings after the change
```

На практике квантиль до изменения оценивают по спокойному периоду. Тогда
гарантия выполняется приближённо, и тем точнее, чем длиннее этот период.

## Выбор ARL

ARL — это компромисс между ложными тревогами и задержкой обнаружения. При
одном показании в минуту ARL в 1000 показаний означает примерно одну ложную
тревогу каждые 17 часов нормальной работы на каждый датчик. При 50 датчиках
это около 70 тревог в сутки. Выбирайте ARL исходя из числа ложных тревог в
сутки, которое вы можете себе позволить по всем датчикам вместе: здесь ARL в
1 000 000 показаний снижает число ложных тревог для 50 датчиков примерно до
одной за две недели. Это обходится дешевле, чем кажется, потому что
задержка обнаружения растёт лишь как логарифм ARL. Для CUSUM порог меняется
с 6,9 до 13,8, а задержка увеличивается примерно вдвое.

Эти детекторы — инструменты мониторинга, а не системы безопасности. Не
используйте их вместо сертифицированной приборной системы безопасности.
