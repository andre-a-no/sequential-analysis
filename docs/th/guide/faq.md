# คำถามที่พบบ่อย

> นี่คือฉบับแปลของ[หน้าภาษาอังกฤษ](../../guide/faq.md) ซึ่งยังไม่ได้รับการตรวจทานโดยเจ้าของภาษา หากสองฉบับมีเนื้อหาต่างกัน ให้ถือหน้าภาษาอังกฤษเป็นหลัก

## เกี่ยวกับไลบรารี

### sequential-analysis คืออะไร?

ไลบรารี Python สำหรับการอนุมานเชิงสถิติแบบลำดับ (sequential inference) การทดสอบ ลำดับช่วงความเชื่อมั่น (confidence sequences) และตัวตรวจจับของไลบรารีนี้สามารถตรวจดูได้หลังทุกค่าสังเกตและหยุดได้ทุกเมื่อ โดยไม่สูญเสียการรับประกันด้านความคลาดเคลื่อน ไลบรารีมี:

* SPRT
* แผนแบบลำดับกลุ่ม (group sequential designs)
* การทดสอบ A/B ที่ใช้ได้ทุกขณะ (anytime-valid)
* ตัวตรวจจับจุดเปลี่ยน
* ตัวกรอง Kalman ตัวกรองอนุภาค และตัวกรองแบบจำลองมาร์คอฟซ่อนเร้น
* การพยากรณ์และ GARCH

ทั้งหมดทำงานภายใต้อินเทอร์เฟซเดียวพร้อมจุดบันทึกสถานะ (checkpoint) แบบ JSON พัฒนาโดย Novikov Laboratories LLC

### ติดตั้งอย่างไร? ต้องพึ่งพาอะไรบ้าง?

`pip install sequential-analysis` ต้องใช้ Python 3.8 ขึ้นไป (ทดสอบถึง 3.14) และไม่ต้องใช้อะไรอื่น `pip install "sequential-analysis[fast]"` จะเพิ่ม numpy สำหรับกระบวนการที่ทำงานกับอาร์เรย์ pandas, polars, ไคลเอนต์ Kafka และ matplotlib จะถูกใช้เฉพาะเมื่อคุณเรียกอะแดปเตอร์หรือฟังก์ชันวาดกราฟ

## การใช้งาน

### ใช้สำหรับการทดสอบ A/B ในระบบจริง (production) ได้หรือไม่?

ได้ ในฐานะเอนจินทางสถิติ ไลบรารีมีการทดสอบแบบแม่นตรง (exact) สำหรับ:

* อัตราคอนเวอร์ชัน (`TwoProportionTest`)
* ตัวชี้วัดที่มีขอบเขต (`BoundedABTest`)
* อัตราเหตุการณ์ (`RateRatioTest`)
* การแบ่งทราฟฟิก (`SampleRatioMismatch`)
* หลายตัวชี้วัดพร้อมการควบคุมอัตราการค้นพบลวง (false discovery rate) (`MultipleTests`)

ใน Python ล้วน การทดสอบอัตราคอนเวอร์ชันใช้เวลาประมาณ 10 ไมโครวินาทีต่อผู้ใช้ การตรวจการแบ่งทราฟฟิก 4 และการทดสอบอัตราเหตุการณ์ 40 จุดบันทึกสถานะของแต่ละตัวมีขนาด 2–4 กิโลไบต์ `BoundedABTest` เก็บกริด (grid) ไว้และใช้เวลา 0.1–0.5 ms

ไลบรารีนี้ไม่ใช่แพลตฟอร์มการทดลอง การสุ่มกลุ่ม การเก็บเหตุการณ์ และแดชบอร์ด เป็นสิ่งที่คุณต้องสร้างเองหรือใช้จากแพลตฟอร์ม ดู[การทดสอบ A/B](ab-testing.md)

### ดูผลทุกวันได้หรือไม่?

ได้ เมื่อใช้กระบวนการที่ใช้ได้ทุกขณะ เพราะนั่นคือสิ่งที่มันถูกสร้างมา หากใช้แผนแบบลำดับกลุ่ม ให้ดูเฉพาะการวิเคราะห์ตามแผน หากใช้การทดสอบแบบขนาดตัวอย่างคงที่แบบดั้งเดิม ให้ดูเพียงครั้งเดียว ดู[การแอบดูผล](peeking.md)

### การทดสอบที่ใช้ได้ทุกขณะมีอำนาจการทดสอบน้อยกว่าการทดสอบแบบขนาดตัวอย่างคงที่หรือไม่?

ณ ขนาดผลที่การทดสอบแบบขนาดตัวอย่างคงที่วางแผนไว้ ใช่ เพื่อให้ได้อำนาจการทดสอบ (power) เท่ากัน การทดสอบสองสัดส่วนที่ใช้ได้ทุกขณะต้องใช้ผู้ใช้ 1.3–1.6 เท่า แลกกับการที่คุณหยุดก่อนได้เมื่อขนาดผลใหญ่กว่า และไม่ต้องกำหนดขนาดตัวอย่างล่วงหน้า แผนแบบลำดับกลุ่มที่ดูผลตามแผนไม่กี่ครั้งมีต้นทุนมากกว่าการวิเคราะห์ครั้งเดียวเพียง 1–20%

### แบบลำดับกลุ่มหรือแบบใช้ได้ทุกขณะ: ควรใช้แบบใด?

* **แบบลำดับกลุ่ม** หากการวิเคราะห์มีไม่กี่ครั้งและวางแผนไว้แล้ว เช่น กับคณะกรรมการกำกับดูแลข้อมูลหรือรอบการออกรุ่นซอฟต์แวร์ และโดยเฉพาะอย่างยิ่งสำหรับการทดลองทางคลินิกเพื่อยืนยันผล
* **แบบใช้ได้ทุกขณะ** หากคุณต้องการดูผลอย่างต่อเนื่อง หรือไม่สามารถบอกล่วงหน้าได้ว่าจะดูหรือหยุดเมื่อใด

### รองรับการทดสอบ A/B แบบเบย์หรือไม่?

การทดสอบ A/B ของไลบรารีเป็นแบบความถี่ (frequentist) ซึ่งมีการรับประกันด้านอัตราความคลาดเคลื่อน มีส่วนประกอบแบบเบย์ในจุดที่เหมาะสม:

* `ThompsonAllocation` ส่งทราฟฟิกตามความน่าจะเป็นภายหลัง (posterior probability) ที่แต่ละกลุ่มจะดีที่สุด พร้อมกฎความสูญเสียคาดหวัง (expected loss) สำหรับการตัดสินใจนำไปใช้จริง
* `BayesianChangePoint` ตรวจจับจุดเปลี่ยน
* ตัวพยากรณ์เรียนรู้พารามิเตอร์ด้วยการปรับปรุงแบบเบย์

### ผ่านการตรวจสอบความถูกต้องสำหรับการทดลองทางคลินิกหรือไม่?

แผนแบบลำดับกลุ่มของไลบรารี (ขอบเขต อำนาจการทดสอบ ขนาดตัวอย่าง จำนวนเหตุการณ์) ได้รับการตรวจสอบเทียบกับ rpact และแพ็กเกจ survival ของ R ในชุดทดสอบ แต่ไลบรารีนี้ไม่ใช่ซอฟต์แวร์ที่ผ่านการตรวจสอบความถูกต้อง (validated) ในความหมายด้านกฎระเบียบ ผู้สนับสนุนการวิจัย (sponsor) ที่ใช้ไลบรารีนี้ในการยื่นเอกสารต้องตรวจสอบความถูกต้องเองเช่นเดียวกับเครื่องมืออื่นใด ดู[การทดลองทางคลินิก](clinical-trials.md)

### ตัวชี้วัดของฉันมีหางหนา (รายได้ เวลาแฝง) ควรใช้อะไร?

* สำหรับควอนไทล์ (มัธยฐาน เปอร์เซ็นไทล์ที่ 90) ให้ใช้ `QuantileTest` หรือ `QuantileConfidenceSequence` ซึ่งไม่ต้องใช้ข้อสมมติใด
* สำหรับค่าเฉลี่ย ให้ตัดเพดานค่าไว้ที่ระดับที่กำหนดล่วงหน้า แล้วใช้ `BoundedABTest` หรือ `BettingConfidenceSequence` (exact)
* อีกทางหนึ่งคือสมมติขอบเขตบนของส่วนเบี่ยงเบนมาตรฐาน แล้วใช้ `CatoniConfidenceSequence`

ไลบรารียังไม่มีการทดสอบมัธยฐานแบบสองตัวอย่าง

### เร็วแค่ไหน?

กระบวนการที่ง่ายที่สุดใช้เวลา 1–10 ไมโครวินาทีต่อค่าสังเกตใน Python ล้วน ได้แก่ SPRT, CUSUM, การทดสอบแบบลำดับกลุ่มและแบบ mixture, GARCH ส่วนกระบวนการที่เก็บกริดหรือตัวอย่างทั้งหมดใช้เวลา 0.1–10 ms ตัวอย่างเช่น ลำดับช่วงความเชื่อมั่นแบบเดิมพันและแบบ Catoni การทดสอบแบบเคอร์เนล และตัวพยากรณ์ที่เรียนรู้ได้ [ความเร็ว](../../performance.md)แสดงต้นทุนและขนาดจุดบันทึกสถานะของแต่ละกระบวนการ

### รันใน JavaScript หรือในเบราว์เซอร์ได้หรือไม่?

ได้ ตัวประมวลผล TypeScript ใน `ts/` รันกระบวนการต่าง ๆ และรันต่อจากจุดบันทึกสถานะของ Python ได้ ไดเจสต์ประวัติและการตัดสินใจเหมือนกันทุกประการ และตัวเลขตรงกันจนถึงบิตท้าย ๆ ดู[ตัวประมวลผล TypeScript](../../typescript.md)

### การรันอยู่รอดจากการล่มของระบบได้หรือไม่?

ได้ `run.checkpoint()` เป็น JSON ธรรมดา และ `Run.restore` รันต่อได้ตรงกันทุกบิต ค่าสังเกตที่ถูกส่งซ้ำจะถูกทิ้ง ดู[สายข้อมูล](streaming.md)

### "exact" และ "asymptotic" ในเอกสารหมายถึงอะไร?

แอตทริบิวต์ `guarantee` ของทุกกระบวนการระบุคำสัญญาของมัน:

* `exact`: อัตราความคลาดเคลื่อนเป็นไปตามที่กำหนดที่ทุกขนาดตัวอย่างภายใต้ข้อสมมติที่ระบุไว้
* `asymptotic`: โดยประมาณ เมื่อรันยาว
* `model`: แม่นตรงภายใต้แบบจำลองที่ระบุ
* `approximate`
* `none`

เอกสารแนะนำให้ใช้กระบวนการแบบ exact เมื่อมีตัวที่เหมาะสม ดู[วิธีใด?](../../choosing.md)
