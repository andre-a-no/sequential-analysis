## लायब्ररीबद्दल

### sequential-analysis म्हणजे काय?

अनुक्रमिक सांख्यिकीय अनुमानासाठी (sequential statistical inference) एक Python
लायब्ररी. तिच्या चाचण्या, विश्वास्यता अनुक्रम (confidence sequences) आणि शोधक
प्रत्येक निरीक्षणानंतर तपासता येतात आणि त्यांच्या त्रुटी हमी न गमावता कोणत्याही
वेळी थांबवता येतात. तिच्यात आहेत:

* SPRT;
* गट अनुक्रमिक अभिकल्प (group sequential designs);
* कधीही-वैध (anytime-valid) A/B चाचण्या;
* बदल-बिंदू शोधक (change-point detectors);
* Kalman, कण (particle) आणि छुपे Markov फिल्टर;
* पूर्वानुमान (forecasting) आणि GARCH.

हे सर्व JSON चेकपॉइंटसह एकाच इंटरफेसमागे चालतात. ती Novikov Laboratories LLC
विकसित करते.

### ती इन्स्टॉल कशी करावी? ती कशावर अवलंबून आहे?

`pip install sequential-analysis`. तिला Python 3.8 किंवा नंतरचे (3.14 पर्यंत
चाचणी केलेले) लागते आणि दुसरे काहीही नाही. `pip install "sequential-analysis[fast]"`
अ‍ॅरेवर काम करणाऱ्या कार्यपद्धतींसाठी numpy जोडते. pandas, polars, Kafka क्लायंट
आणि matplotlib फक्त तुम्ही अ‍ॅडॅप्टर किंवा प्लॉटिंग फंक्शन्स वापरल्यासच वापरले
जातात.

## वापर

### उत्पादनात (production) A/B चाचण्यांसाठी ती वापरता येईल का?

होय, सांख्यिकीय इंजिन म्हणून. ती यांसाठी अचूक चाचण्या देते:

* रूपांतरण (`TwoProportionTest`);
* मर्यादित मेट्रिक्स (`BoundedABTest`);
* दर (`RateRatioTest`);
* ट्रॅफिकची विभागणी (`SampleRatioMismatch`);
* खोट्या शोधांच्या दराच्या (false discovery rate) नियंत्रणासह अनेक मेट्रिक्स
  (`MultipleTests`).

शुद्ध Python मध्ये रूपांतरण चाचणीला प्रति वापरकर्ता सुमारे 10 मायक्रोसेकंद
लागतात, विभागणी तपासणीला 4 आणि दर चाचणीला 40. प्रत्येकाचा चेकपॉइंट 2–4 किलोबाइट
घेतो.
`BoundedABTest` एक ग्रिड ठेवते आणि 0.1–0.5 ms घेते.

ही लायब्ररी प्रयोग प्लॅटफॉर्म नाही: वाटप (assignment), घटना संकलन आणि डॅशबोर्ड
तुम्हाला स्वतः तयार करावे लागतील किंवा एखाद्या प्लॅटफॉर्मवरून घ्यावे लागतील.
पाहा [A/B चाचण्या](ab-testing.md).

### मी निकालांवर रोज डोकावू शकतो का?

होय, कधीही-वैध कार्यपद्धतींसह: त्या याचसाठी आहेत. गट अनुक्रमिक अभिकल्पात फक्त
नियोजित विश्लेषणांवरच पाहा. शास्त्रीय स्थिर-नमुना चाचणीत एकदाच पाहा. पाहा
[डोकावणे](peeking.md).

### कधीही-वैध चाचणी स्थिर-नमुना चाचणीपेक्षा कमी सामर्थ्यवान असते का?

स्थिर-नमुना चाचणी ज्या परिणामासाठी नियोजित केलेली असते त्यावर, होय. तेवढेच
सामर्थ्य (power) गाठण्यासाठी दोन प्रमाणांच्या कधीही-वैध चाचणीला 1.3–1.6 पट
वापरकर्ते लागतात. त्याबदल्यात परिणाम मोठा असल्यास तुम्ही लवकर थांबू शकता, आणि
आधीपासून कोणताही नमुना आकार ठरवावा लागत नाही. काही नियोजित पाहण्यांसह गट
अनुक्रमिक अभिकल्पाची किंमत एकाच विश्लेषणापेक्षा फक्त 1–20% अधिक असते.

### गट अनुक्रमिक की कधीही-वैध: कोणते वापरावे?

* **गट अनुक्रमिक**, जर विश्लेषणे थोडी आणि नियोजित असतील, जसे डेटा देखरेख
  समिती किंवा रिलीज चक्रात, आणि विशेषतः पुष्टीकारक (confirmatory) वैद्यकीय
  चाचणीसाठी.
* **कधीही-वैध**, जर तुम्हाला सतत पाहायचे असेल, किंवा तुम्ही केव्हा पाहाल किंवा
  थांबाल हे आधी सांगता येत नसेल.

### ती बेझियन A/B चाचणी करते का?

तिच्या A/B चाचण्या वारंवारितावादी (frequentist) आहेत, त्रुटी दरांवरील हमींसह.
जिथे योग्य तिथे बेझियन घटक उपलब्ध आहेत:

* `ThompsonAllocation` प्रत्येक शाखा सर्वोत्तम असण्याच्या उत्तर संभाव्यतेनुसार
  (posterior probability) ट्रॅफिक पाठवते, उपयोजनासाठी (deployment) अपेक्षित-तोटा
  (expected-loss) नियमासह;
* `BayesianChangePoint` बदल-बिंदू ओळखते;
* पूर्वानुमानक (forecasters) बेझियन अद्ययावतीकरणाने आपले प्राचल शिकतात.

### वैद्यकीय चाचण्यांसाठी ती प्रमाणित (validated) आहे का?

तिचे गट अनुक्रमिक अभिकल्प (सीमा, सामर्थ्य, नमुना आकार, घटनांच्या संख्या) चाचणी
संचात rpact आणि R च्या survival पॅकेजशी पडताळले जातात. नियामक अर्थाने हे
प्रमाणित सॉफ्टवेअर नाही. सादरीकरणासाठी ती वापरणारा प्रायोजक इतर कोणत्याही
साधनाप्रमाणे तिचे प्रमाणीकरण करतो. पाहा [वैद्यकीय चाचण्या](clinical-trials.md).

### माझे मेट्रिक जड-पुच्छ आहे (महसूल, विलंब). मी काय वापरावे?

* विभाजकासाठी (quantile) (मध्यका, 90 वे शतमक), `QuantileTest` किंवा
  `QuantileConfidenceSequence` वापरा, ज्यांना कोणत्याही गृहीतकांची गरज नसते.
* सरासरीसाठी, आधीपासून ठरवलेल्या पातळीवर मूल्यांची कमाल मर्यादा लावा आणि
  `BoundedABTest` किंवा `BettingConfidenceSequence` (exact) वापरा.
* पर्यायाने, प्रमाण विचलनावर मर्यादा गृहीत धरा आणि `CatoniConfidenceSequence`
  वापरा.

मध्यकांची द्वि-नमुना चाचणी अजून लायब्ररीत नाही.

### ती किती वेगवान आहे?

सर्वात सोप्या कार्यपद्धतींना शुद्ध Python मध्ये प्रति निरीक्षण 1–10 मायक्रोसेकंद
लागतात: SPRT, CUSUM, गट अनुक्रमिक आणि मिश्रण (mixture) चाचण्या, GARCH. ग्रिड
किंवा संपूर्ण नमुना ठेवणाऱ्यांना 0.1–10 ms लागतात. उदाहरणे म्हणजे पैज (betting)
आणि Catoni विश्वास्यता अनुक्रम, कर्नल चाचणी आणि शिकलेले पूर्वानुमानक.
[वेग](../../performance.md) प्रत्येक कार्यपद्धतीचा खर्च आणि चेकपॉइंट आकार देते.

### ती JavaScript मध्ये किंवा ब्राउझरमध्ये चालवता येईल का?

होय. `ts/` मधील TypeScript एक्झिक्युटर कार्यपद्धती चालवतो आणि Python चेकपॉइंट
पुढे चालू ठेवतो. इतिहास डायजेस्ट (history digests) आणि निर्णय एकसारखे असतात, आणि
आकडे शेवटच्या बिट्सपर्यंत जुळतात. पाहा [TypeScript एक्झिक्युटर](../../typescript.md).

### रन क्रॅशमधून टिकू शकतो का?

होय. `run.checkpoint()` साधे JSON आहे, आणि `Run.restore` बिट-दर-बिट पुढे चालू
ठेवते. पुन्हा पोहोचवलेली निरीक्षणे वगळली जातात. पाहा
[प्रवाह प्रक्रिया](streaming.md).

### दस्तऐवजीकरणात "exact" आणि "asymptotic" यांचा अर्थ काय?

प्रत्येक कार्यपद्धतीचा `guarantee` गुणधर्म तिचे वचन नमूद करतो:

* `exact`: नमूद केलेल्या गृहीतकांखाली प्रत्येक नमुना आकारावर त्रुटी दर टिकतो;
* `asymptotic`: अंदाजे, लांब रनमध्ये;
* `model`: नमूद केलेल्या प्रतिमानाखाली अचूक;
* `approximate`;
* `none`.

जिथे अचूक कार्यपद्धती लागू होते तिथे दस्तऐवजीकरण तिचीच शिफारस करते. पाहा
[कोणती पद्धत?](../../choosing.md).
