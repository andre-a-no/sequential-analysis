# よくある質問

## ライブラリについて

### sequential-analysis とは何ですか？

逐次的な統計的推論（sequential statistical inference）のための Python ライブラリです。その検定、信頼系列（confidence sequence）、検出器は、観測のたびに確認でき、誤差の保証を失うことなくいつでも止められます。次のものを備えています。

* SPRT
* 群逐次デザイン（group sequential design）
* 常時有効（anytime-valid）な A/B テスト
* 変化点検出器
* カルマンフィルタ、粒子フィルタ、隠れマルコフフィルタ
* 予測と GARCH

これらはすべて、JSON チェックポイントを備えた 1 つのインターフェースの背後で動作します。開発元は Novikov Laboratories LLC です。

### インストール方法は？ 何に依存していますか？

`pip install sequential-analysis`。Python 3.8 以降（3.14 までテスト済み）が必要で、それ以外は何も要りません。`pip install "sequential-analysis[fast]"` とすると、配列を扱う手続きのために numpy が追加されます。pandas、polars、Kafka クライアント、matplotlib は、アダプタやプロット関数を呼び出した場合にのみ使われます。

## 使い方

### 本番環境の A/B テストに使えますか？

はい、統計エンジンとして使えます。次のものに対する正確な検定を提供します。

* コンバージョン（`TwoProportionTest`）
* 有界な指標（`BoundedABTest`）
* レート（`RateRatioTest`）
* トラフィックの分割（`SampleRatioMismatch`）
* 偽発見率の制御を伴う多数の指標（`MultipleTests`）

純粋な Python で、コンバージョンの検定はユーザーあたり約 10 マイクロ秒、分割のチェックは 4 マイクロ秒、レートの検定は 40 マイクロ秒かかります。それぞれのチェックポイントは 2〜4 キロバイトです。
`BoundedABTest` はグリッドを保持し、0.1〜0.5 ms かかります。

このライブラリは実験プラットフォームではありません。割り付け、イベント収集、ダッシュボードは、自分で構築するかプラットフォームから取り入れる必要があります。[A/B テスト](ab-testing.md)を参照してください。

### 結果を毎日のぞき見してもよいですか？

はい、常時有効な手続きであれば。それこそがその目的です。
群逐次デザインでは、計画した解析の時点でのみ見てください。
古典的な固定標本サイズの検定では、見るのは 1 回だけです。[のぞき見](peeking.md)を参照してください。

### 常時有効な検定は固定標本サイズの検定より検出力が低いのですか？

固定標本サイズの検定が計画された効果のもとでは、そのとおりです。同じ検出力に達するには、2 つの割合の常時有効な検定は 1.3〜1.6 倍のユーザーを必要とします。その代わり、効果が大きければ早く止められ、サンプルサイズを事前に決める必要もありません。計画した確認が数回の群逐次デザインなら、1 回の解析に比べて 1〜20% 多いだけで済みます。

### 群逐次と常時有効、どちらを使うべきですか？

* **群逐次**：データモニタリング委員会やリリースサイクルのように、解析が少数で計画されている場合。特に検証的臨床試験に向いています。
* **常時有効**：継続的に見たい場合、あるいはいつ見るか・いつ止めるかを事前に決められない場合。

### ベイズ流の A/B テストはできますか？

A/B テストは頻度論的なもので、誤り率に対する保証があります。
適した場面ではベイズ的なコンポーネントが使えます。

* `ThompsonAllocation` は、各群が最良である事後確率に従ってトラフィックを振り分け、デプロイのための期待損失ルールを備えています
* `BayesianChangePoint` は変化点を検出します
* 予測器はベイズ更新によってパラメータを学習します

### 臨床試験向けにバリデーションされていますか？

群逐次デザイン（境界、検出力、サンプルサイズ、イベント数）は、テストスイートで rpact および R の survival パッケージと照合されています。規制上の意味でバリデーションされたソフトウェアではありません。申請に使用する治験依頼者は、他のツールと同様にバリデーションを行います。[臨床試験](clinical-trials.md)を参照してください。

### 指標の裾が重い（売上、レイテンシ）場合は何を使えばよいですか？

* 分位点（中央値、90 パーセンタイル）には、仮定を必要としない `QuantileTest` または `QuantileConfidenceSequence` を使います。
* 平均には、事前に決めた水準で値に上限を設け、`BoundedABTest` または `BettingConfidenceSequence`（正確）を使います。
* あるいは、標準偏差の上限を仮定して `CatoniConfidenceSequence` を使います。

中央値の 2 標本検定はまだライブラリにありません。

### どのくらい速いですか？

最も単純な手続きは、純粋な Python で観測あたり 1〜10 マイクロ秒です：SPRT、CUSUM、群逐次検定と混合検定、GARCH。
グリッドや標本全体を保持するものは 0.1〜10 ms かかります。例としては、ベッティングと Catoni の信頼系列、カーネル検定、学習型の予測器があります。
[速度](../../performance.md)に各手続きのコストとチェックポイントのサイズが一覧になっています。

### JavaScript やブラウザで実行できますか？

はい。`ts/` にある TypeScript 実行系は、手続きを実行し、Python のチェックポイントを引き継げます。履歴ダイジェストと判定は同一で、数値は最後の数ビットまで一致します。[TypeScript 実行系](../../typescript.md)を参照してください。

### 実行はクラッシュから復旧できますか？

はい。`run.checkpoint()` はプレーンな JSON で、`Run.restore` はビット単位で完全に続行します。再配信された観測は破棄されます。[ストリーミング](streaming.md)を参照してください。

### ドキュメント中の「exact」と「asymptotic」はどういう意味ですか？

すべての手続きの `guarantee` 属性が、その約束を表しています。

* `exact`：述べられた仮定のもとで、誤り率がすべてのサンプルサイズで成り立つ
* `asymptotic`：長い実行で近似的に成り立つ
* `model`：述べられたモデルのもとで正確
* `approximate`
* `none`

ドキュメントでは、適用できる正確な手続きがあればそれを推奨しています。[どの手法を選ぶか？](../../choosing.md)を参照してください。
