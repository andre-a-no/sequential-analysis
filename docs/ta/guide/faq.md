# அடிக்கடி கேட்கப்படும் கேள்விகள்

> இது [ஆங்கிலப் பக்கத்தின்](../../guide/faq.md) மொழிபெயர்ப்பு. தமிழைத் தாய்மொழியாகக் கொண்ட ஒருவர் இதை இன்னும் மதிப்பாய்வு செய்யவில்லை; இரண்டுக்கும் இடையே வேறுபாடு இருந்தால், ஆங்கிலப் பக்கமே அதிகாரப்பூர்வமானது.

## நூலகம் பற்றி

### sequential-analysis என்றால் என்ன?

தொடர்முறைப் புள்ளியியல் அனுமானத்துக்கான (sequential statistical inference) ஒரு
Python நூலகம். அதன் சோதனைகள், நம்பகத் தொடர்கள் (confidence sequences) மற்றும்
கண்டறிவிகளை ஒவ்வொரு கவனிப்புக்குப் பிறகும் சரிபார்க்கலாம், அவற்றின் பிழை
உத்தரவாதங்களை இழக்காமல் எந்த நேரத்திலும் நிறுத்தலாம். அதில் உள்ளவை:

* SPRT-கள்;
* குழுத் தொடர்முறை வடிவமைப்புகள் (group sequential designs);
* எப்போதும்-செல்லுபடியான (anytime-valid) A/B சோதனைகள்;
* மாற்றப் புள்ளி கண்டறிவிகள் (change-point detectors);
* Kalman, துகள் (particle) மற்றும் மறை Markov வடிகட்டிகள்;
* முன்கணிப்பு (forecasting) மற்றும் GARCH.

இவை அனைத்தும் JSON சோதனைப்புள்ளிகளுடன் ஒரே இடைமுகத்தின் பின்னால் இயங்குகின்றன.
இதை Novikov Laboratories LLC உருவாக்குகிறது.

### இதை எப்படி நிறுவுவது? இது எதைச் சார்ந்துள்ளது?

`pip install sequential-analysis`. இதற்கு Python 3.8 அல்லது அதற்குப் பிந்தையது
(3.14 வரை சோதிக்கப்பட்டது) தேவை, வேறு எதுவும் தேவையில்லை.
`pip install "sequential-analysis[fast]"` வரிசைகள் (arrays) மீது செயல்படும்
செயல்முறைகளுக்காக numpy-ஐச் சேர்க்கிறது. pandas, polars, Kafka கிளையன்ட்கள் மற்றும்
matplotlib, நீங்கள் இணைப்பிகளையோ (adapters) வரைவுச் செயல்பாடுகளையோ அழைத்தால்
மட்டுமே பயன்படுத்தப்படுகின்றன.

## பயன்படுத்துதல்

### உற்பத்திச் சூழலில் (production) A/B சோதனைகளுக்கு இதைப் பயன்படுத்தலாமா?

ஆம், புள்ளியியல் இயந்திரமாக. இது துல்லியமான சோதனைகளைத் தருவது:

* மாற்றத்துக்கு (`TwoProportionTest`);
* வரம்புக்குட்பட்ட அளவீடுகளுக்கு (`BoundedABTest`);
* விகிதங்களுக்கு (`RateRatioTest`);
* போக்குவரத்துப் பிரிப்புக்கு (`SampleRatioMismatch`);
* தவறான கண்டுபிடிப்பு விகிதக் (false discovery rate) கட்டுப்பாட்டுடன் பல
  அளவீடுகளுக்கு (`MultipleTests`).

தூய Python-இல் மாற்றச் சோதனை ஒரு பயனருக்குச் சுமார் 10 மைக்ரோவினாடிகள் எடுக்கிறது,
பிரிப்புச் சரிபார்ப்பு 4, விகிதச் சோதனை 40. ஒவ்வொன்றின் சோதனைப்புள்ளியும்
2–4 கிலோபைட் எடுக்கிறது.
`BoundedABTest` ஒரு கட்டத்தை (grid) வைத்திருக்கிறது, 0.1–0.5 ms எடுக்கிறது.

இந்த நூலகம் ஒரு சோதனைத் தளம் அல்ல: ஒதுக்கீடு (assignment), நிகழ்வுச் சேகரிப்பு
மற்றும் டாஷ்போர்டுகளை நீங்களே உருவாக்க வேண்டும் அல்லது ஒரு தளத்திலிருந்து பெற
வேண்டும். காண்க [A/B சோதனைகள்](ab-testing.md).

### முடிவுகளைத் தினமும் எட்டிப்பார்க்கலாமா?

ஆம், எப்போதும்-செல்லுபடியான செயல்முறைகளுடன்: அவை அதற்காகவே உள்ளன. குழுத்
தொடர்முறை வடிவமைப்பில், திட்டமிட்ட பகுப்பாய்வுகளில் மட்டுமே பாருங்கள். மரபான
நிலையான-மாதிரிச் சோதனையில், ஒருமுறை மட்டுமே பாருங்கள். காண்க
[எட்டிப்பார்த்தல்](peeking.md).

### எப்போதும்-செல்லுபடியான சோதனை நிலையான-மாதிரிச் சோதனையைவிடக் குறைந்த திறன் கொண்டதா?

நிலையான-மாதிரிச் சோதனை திட்டமிடப்பட்ட விளைவில், ஆம். அதே திறனை (power) அடைய,
இரு விகிதங்களுக்கான எப்போதும்-செல்லுபடியான சோதனைக்கு 1.3–1.6 மடங்கு பயனர்கள் தேவை.
அதற்கு ஈடாக, விளைவு பெரிதாக இருந்தால் முன்கூட்டியே நிறுத்தலாம், முன்கூட்டியே
நிர்ணயித்த மாதிரி அளவு எதுவும் தேவையில்லை. சில திட்டமிட்ட பார்வைகள் கொண்ட குழுத்
தொடர்முறை வடிவமைப்புக்கு ஒற்றைப் பகுப்பாய்வைவிட 1–20% மட்டுமே கூடுதல் செலவு.

### குழுத் தொடர்முறையா எப்போதும்-செல்லுபடியானதா: எதைப் பயன்படுத்துவது?

* **குழுத் தொடர்முறை**: பகுப்பாய்வுகள் குறைவாகவும் திட்டமிடப்பட்டவையாகவும்
  இருந்தால், தரவுக் கண்காணிப்புக் குழு அல்லது வெளியீட்டுச் சுழற்சியில் இருப்பது
  போல, குறிப்பாக உறுதிப்படுத்தும் (confirmatory) மருத்துவ ஆய்வுக்கு.
* **எப்போதும்-செல்லுபடியானது**: நீங்கள் தொடர்ச்சியாகப் பார்க்க விரும்பினால், அல்லது
  எப்போது பார்ப்பீர்கள் அல்லது நிறுத்துவீர்கள் என்பதை முன்கூட்டியே சொல்ல முடியாவிட்டால்.

### இது பேய்சியன் A/B சோதனை செய்கிறதா?

இதன் A/B சோதனைகள் அலைவெண்வாத (frequentist) சோதனைகள், பிழை விகிதங்கள் மீதான
உத்தரவாதங்களுடன். பொருந்தும் இடங்களில் பேய்சியன் கூறுகள் கிடைக்கின்றன:

* `ThompsonAllocation` ஒவ்வொரு கிளையும் சிறந்தது என்பதற்கான பின் நிகழ்தகவின்
  (posterior probability) அடிப்படையில் போக்குவரத்தை அனுப்புகிறது, வரிசைப்படுத்தலுக்கு
  (deployment) எதிர்பார்க்கப்படும்-இழப்பு (expected-loss) விதியுடன்;
* `BayesianChangePoint` மாற்றப் புள்ளிகளைக் கண்டறிகிறது;
* முன்கணிப்பிகள் (forecasters) பேய்சியன் புதுப்பித்தல் மூலம் தங்கள் அளவுருக்களைக்
  கற்கின்றன.

### மருத்துவ ஆய்வுகளுக்கு இது சரிபார்க்கப்பட்டதா (validated)?

இதன் குழுத் தொடர்முறை வடிவமைப்புகள் (எல்லைகள், திறன், மாதிரி அளவுகள், நிகழ்வுகளின்
எண்ணிக்கைகள்) சோதனைத் தொகுப்பில் rpact மற்றும் R-இன் survival தொகுப்புடன்
சரிபார்க்கப்படுகின்றன. ஒழுங்குமுறை அர்த்தத்தில் இது சரிபார்க்கப்பட்ட மென்பொருள்
அல்ல. ஒரு சமர்ப்பிப்புக்கு இதைப் பயன்படுத்தும் ஆதரவாளர் வேறு எந்தக் கருவியையும்
போலவே இதைச் சரிபார்க்கிறார். காண்க [மருத்துவ ஆய்வுகள்](clinical-trials.md).

### என் அளவீடு கனத்த வால்கள் கொண்டது (வருவாய், தாமதம்). நான் எதைப் பயன்படுத்த வேண்டும்?

* ஒரு கணுமத்துக்கு (quantile) (இடைநிலை, 90-ஆவது சதமானம்), `QuantileTest` அல்லது
  `QuantileConfidenceSequence`-ஐப் பயன்படுத்துங்கள், அவற்றுக்கு எந்த அனுமானமும்
  தேவையில்லை.
* ஒரு சராசரிக்கு, முன்கூட்டியே நிர்ணயித்த நிலையில் மதிப்புகளுக்கு உச்சவரம்பு இட்டு,
  `BoundedABTest` அல்லது `BettingConfidenceSequence` (exact) பயன்படுத்துங்கள்.
* மாற்றாக, திட்ட விலக்கத்தின் மீது ஒரு வரம்பை அனுமானித்து
  `CatoniConfidenceSequence`-ஐப் பயன்படுத்துங்கள்.

இடைநிலைகளுக்கான இரு-மாதிரிச் சோதனை இன்னும் நூலகத்தில் இல்லை.

### இது எவ்வளவு வேகமானது?

எளிமையான செயல்முறைகள் தூய Python-இல் ஒரு கவனிப்புக்கு 1–10 மைக்ரோவினாடிகள்
எடுக்கின்றன: SPRT-கள், CUSUM, குழுத் தொடர்முறை மற்றும் கலவை (mixture) சோதனைகள்,
GARCH. ஒரு கட்டத்தையோ முழு மாதிரியையோ வைத்திருப்பவை 0.1–10 ms எடுக்கின்றன.
எடுத்துக்காட்டுகள்: பந்தயம் (betting) மற்றும் Catoni நம்பகத் தொடர்கள், கெர்னல்
சோதனை, கற்ற முன்கணிப்பிகள்.
[வேகம்](../../performance.md) ஒவ்வொரு செயல்முறையின் செலவையும் சோதனைப்புள்ளி
அளவையும் பட்டியலிடுகிறது.

### இதை JavaScript-இல் அல்லது உலாவியில் இயக்கலாமா?

ஆம். `ts/`-இல் உள்ள TypeScript இயக்கி செயல்முறைகளை இயக்குகிறது, Python
சோதனைப்புள்ளிகளைத் தொடர்கிறது. வரலாற்றுச் செரிமானங்களும் (history digests)
முடிவுகளும் ஒன்றே, எண்கள் கடைசி பிட்டுகள் வரை ஒத்துப்போகின்றன. காண்க
[TypeScript இயக்கி](../../typescript.md).

### ஓர் ஓட்டம் செயலிழப்பைத் தாங்குமா?

மீண்டும் வழங்கப்படும் கவனிப்புகள் கைவிடப்படுகின்றன. காண்க
[தொடரோட்டச் செயலாக்கம்](streaming.md).

### ஆவணங்களில் "exact" மற்றும் "asymptotic" என்பதன் பொருள் என்ன?

ஒவ்வொரு செயல்முறையின் `guarantee` பண்புக்கூறும் அதன் உறுதிமொழியைக் கூறுகிறது:

* `exact`: குறிப்பிட்ட அனுமானங்களின் கீழ் ஒவ்வொரு மாதிரி அளவிலும் பிழை விகிதம்
  நிலைக்கிறது;
* `asymptotic`: தோராயமாக, நீண்ட ஓட்டங்களில்;
* `model`: குறிப்பிட்ட மாதிரியுருவின் கீழ் துல்லியமானது;
* `approximate`;
* `none`.

துல்லியமான செயல்முறை பொருந்தும் இடத்தில் ஆவணங்கள் அதையே பரிந்துரைக்கின்றன. காண்க
[எந்த முறை?](../../choosing.md).
